# QR system — feature module (in progress)

Owns everything QR: generating the session QR (host) and scanning it
(student). One team, one module, both apps use it.

## Public interface (what other code may call)

```kotlin
// Host side — generate a QR bitmap from text (the session ID).
QrGenerator.bitmap(text: String): Bitmap

// Student side — scan a QR with the camera, report the text or an error.
// Exact scanner API is the team's design decision — propose it in an
// issue before building. CameraX + ZXing / ML Kit are the expected tools.
QrScanner.start(onResult: (Result<String>) -> Unit)
QrScanner.stop()
```

## Contract

- QR payload is exactly the session ID: `ATT-` + 8 uppercase hex chars
  (contract §3). Anything else scanned is "not our session" — show an
  error, never crash.
- This module never touches the network, Bluetooth, or permissions
  directly — camera permission goes through the permissions system.

## Where the code comes from

- The generator already exists as `QrCode.kt` in the host app. Moving it
  here is a tracked issue — move, wire the host app to this module,
  test, merge.
- The scanner is new work (student app). Test it against a printed QR
  or the generator in this same module — no waiting for the host app.

## Done when

- Host app shows a QR generated by this module.
- Student app scans a QR and gets the session ID back (or a clean error).
- The module builds and its tests pass on their own, without the apps.
